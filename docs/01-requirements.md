## 1. 项目目标与范围

### 1.1 目标

提供PC桌面浏览器中的《40阶登山博弈游戏》。玩家先选角、抛硬币并交替选取猜拳牌，再在开局唯一准备阶段兑换手牌与炸弹、秘密布雷，随后通过同时亮牌的猜拳对战登山。支持本地双人、AI、房间码邀请联机三种模式。

界面采用《原神》白昼天空岛圣殿与笔直向上的立体天梯风格，以程序化立体角色、阶数高亮、镜头跟随、背景音乐及音效呈现游戏过程。该视觉裁决取代初稿的“盘山阶梯”要求。

前端LocalStorage在同一浏览器同源站点范围内保存多个本地账号，各账号分别保留战绩、角色解锁进度和设置。无需外部数据库；不提供云账号、跨设备恢复、未完对局保存或断线续局。

### 1.2 阶段与交付约束

本轮同步四阶段文档中的表现层需求，不创建程序源代码、不安装依赖。技术约束为原生Web：HTML5 Canvas + SVG/Canvas铭牌与元素信标 + CSS3 3D视差光影 + Web Audio API；首页与账号系统沿用同一工程。

流程保持为：需求分析 → 系统分析 → 系统设计 → 开发任务拆分 → AI生成程序 → 人工运行测试 → 反馈修改 → 最终验收。每阶段完成后由用户确认；进入程序开发还必须等待用户明确说“开始编程”。删除任何文件必须先征得用户允许。

### 1.3 v1.1修订范围与优先级

本版在既有账号、三种模式、地图、音频和基础博弈规则上，完整增加13名角色的名字铭牌/元素信标及技能、主动技能释放规则、魔神压制、回溯、AI手动选角、融合角色测试解锁/重置和重新开始；本次补充确认双方先完成技能选择、再选牌锁定，以及阿斯莫代只查看/移动己方雷并在取消时返还暂扣次数。角色表见3.10节，技能之间的结算及信息授权边界见3.11～3.13节。

需求优先级为：用户最新明确补充及答复 → 角色特定技能规则 → 仍适用的v1.0基础规则。新增技能是普通准备限制、信息保密及默认移动规则的明确例外，不因此开放任意玩家在任意时点兑换、布雷或查看敌方信息。Q-01～Q-12继续保持已闭合，原记录按v1.1明确例外解释。

两首特殊曲目《Termination of Desires》《Rage Beneath the Mountains》继续内置可手动播放；本次虽给出角色名单，但没有指定它们与角色的自动触发映射，因此本版保留原四首自动场景映射，不擅自将某首曲目绑定某角色。该映射作为后续需求补充点，与本次已明确的角色技能分别记录。

聊天、公屏、公开匹配、观战、排行榜、付费、云同步不在本版范围。所有交付均为需求文档，不是程序实现。
### 1.4 编号与状态约定

FR为功能需求，BR为业务规则，UC为用例，AC为未来人工验收标准，NFR为非功能需求。Q-01～Q-12保留为**已裁决、已闭合的决定记录**，不再作为待确认清单。

本版保留既有FR-01～FR-55、UC-01～UC-28、AC-01～AC-60编号并修订其适用范围，新增编号顺延；CH编号对应13名角色。AC定义的是验收口径，文档检查不代表软件功能、音画或性能已通过验收。第3.9节列出把最终裁决衔接成完整流程所采用的边界解释，避免将其误称为用户另行指定的细节。

## 2. 系统参与者分析

### 2.1 外部参与者

| 编号 | 参与者 | 目标与职责 | 边界 |
| --- | --- | --- | --- |
| ACT-01 | 未登录使用者 | 在登录/注册模态框中注册或登录 | 首次打开为未登录状态，不能免登录进入首页；不是Guest_P2 |
| ACT-02 | 本地账号使用者 | 查看首页、战绩及解锁进度，管理设置和音乐，开始对战、创建或加入房间 | 当前客户端只有一个登录主账号；账号切换/退出仅允许在首页操作 |
| ACT-03 | 对局玩家（P1/P2） | 选角、就绪、选牌、准备、施放角色技能、出牌、查看本人/获授权信息及结果、申请重开 | 是业务席位角色；本地和联机有两位人类，AI模式仅人类是外部参与者 |
| ACT-04 | 本地临时访客Guest_P2 | 在主账号发起的本地对局中操作P2 | ACT-03的特化；无需第二账号，不独立保存战绩、成就或设置，不具有ACT-02的账号管理权限 |

同一人可在首页扮演ACT-02，在对局扮演ACT-03。房主、受邀者、先手和后手是场景身份，不是额外账号类型。

### 2.2 席位与账号归属

| 模式 | P1 | P2 | 本客户端保存对象 |
| --- | --- | --- | --- |
| 本地双人 | 当前登录主账号 | Guest_P2 | 仅主账号，按P1视角记录 |
| AI对战 | 当前登录主账号 | 系统AI | 仅主账号；AI不独立建档 |
| 联机对战 | 创建房间的房主 | 输入房间码加入者 | 各客户端只保存自己当前主账号；加入者按P2视角记录，不替对手账号写入 |

本地不允许同一主账号同时占P1/P2并计算两份战绩。联机房主固定P1不代表必定先选牌；选牌先手由公平硬币决定。

### 2.3 相关方及系统边界

教师和验收人员是项目评审相关方，不因此增加后台管理功能。AI、LocalStorage、地图、计时器、播放器、合成器均属于系统内部能力或运行环境，不作为外部参与者。用例图不虚构外部数据库、云账号或音乐服务。

联机允许采用同机多窗口/跨标签页的BroadcastChannel加LocalStorage事件同步，或轻量级局域网消息同步；具体方案在系统设计阶段选择。本版不承诺公网异地联机，也不将同源本地存储描述为跨设备共享账号。

## 3. 业务规则与验收解释

### 3.1 术语

| 术语 | 定义 |
| --- | --- |
| 公共牌库 | 初始石头、剪刀、布各30张，共90张；初选及库存雷换牌从中取牌 |
| 可用手牌 | 本人尚可选取进行兑换或出牌的牌；确认出牌后扣除，揭示前不公开其花色 |
| 秘密销毁区 | 存放普通或技能牌换雷的消耗牌、雷炸随机弃牌；不回库、不公开花色，与已亮出的公开出牌历史分离；合法回溯可恢复相应资源 |
| 公开出牌历史 | 在应出牌者均锁定、统一揭示后，记录双方实际打出的牌；包括败方、平局和单向出牌，不回库 |
| 库存炸弹 | 本人未布置的炸弹；只有该类炸弹可用于“1雷换2牌” |
| 场上炸弹 | 放在1～39阶、具有所有者且尚未引爆的炸弹 |
| 一次落脚 | 前进结束或一次爆炸回退结束后到达某阶；不包含途中经过、原地停留和视觉站位偏移 |
| 房间准备就绪 | 联机双方进入房间后各点击就绪，二者完成后启动选角；不同于选牌后的唯一准备阶段 |
| 唯一准备阶段 | 双方各取满30张牌后、第1回合之前的一次性兑换、布雷及锁定阶段 |
| 领先高度 | 双方当前所在阶数的最大值；自动BGM另记本局已达到的最高音乐区间以避免爆炸降级回切 |
| 当前客户端主账号 | 本客户端已登录且从选角至对局结束期间被锁定的账号；联机加入者可以位于P2 |

### 3.2 业务流程

登录/注册 → 首页选择模式 → 确定席位（联机先入房并双方就绪）→ 选择角色 → 初始化资源并抛硬币 → 一人一张交替初选至双方各30张 → 唯一准备阶段 → 双方锁定后统一公开规定信息 → 每轮在出牌界面先完成出牌前主动技能选择与确认，再暗选锁牌、亮牌、移动及连锁结算 → 本轮结果展示及可用的伊斯塔露回溯操作 → 确认登顶/耗尽结果 → 保存主账号结果 → 返回首页。

本地准备采用硬币确定的先手先操作、锁定、交接遮罩、后手操作并锁定；AI及联机双方独立准备。图中的include/extend只表示必需子目标或条件行为，不用于表达上述先后顺序。

### 3.3 基础规则

| 编号 | 规则 |
| --- | --- |
| BR-01 | 初始公共牌90张、各花色30，双方0阶；默认各3库存雷，巴尔泽布改为4；每次新局重新初始化，不继承旧局资源或技能次数 |
| BR-02 | 公平硬币正反各1/2；正面P1先选，反面P2先选；之后一人一张交替，直至各30张 |
| BR-03 | 初选结束双方共取60张、公共库剩30张；先手影响选牌、本地准备及本版明确的同轮冲突定序；不赋予猜拳胜负优势，同轮同时登顶不以先手优先 |
| BR-04 | 普通准备仍仅一次，首回合后普通兑换/布雷/撤雷入口关闭；阿斯莫代移雷、若娜瓦牌换雷并布置等明确角色技能在出牌界面按专属条件执行 |
| BR-05 | 默认本人库存＋本人场上雷上限4，巴尔泽布为5；所有普通操作及技能均遵守施法者/雷所有者的适用上限，移动和撤回不改变雷归属或释放额度 |
| BR-06 | 默认准备以2指定牌换1库存雷；有效黄金莱茵多特被动使本局准备首次成功牌换雷只需1牌；消耗进入秘密销毁区，不返公共库 |
| BR-07 | 默认准备1库存雷换2牌；未受压制的纳贝里士来源被动改为3牌，融合角色同样适用；按剩余实体牌等概率不放回抽取，库不足本次应得张数则整体拒绝 |
| BR-08 | 准备在资源约束内不限制兑换次数；联机仍受准备确认倒计时约束；结束后手牌按实际数量保留，不重置成30 |
| BR-09 | 普通雷限1～39且可同阶多枚；准备未锁定可移动/撤回本人本次布置雷，锁定后普通调整禁止。阿斯莫代仅可在出牌界面查看并移动己方布置雷，不显示或移动敌雷；放雷/移雷到角色脚下不等于角色移动，不立即触发 |
| BR-10 | 双方有牌时各暗选1张，确认前可改选、确认后不可改；应出牌者全部锁定后同时亮牌；石头胜剪刀、剪刀胜布、布胜石头 |
| BR-11 | 基础胜者剪刀2、布3、石头5；风剪刀胜4、岩石头胜6、水布胜5；火连续至少2轮真实猜拳获胜时加2。平局/败方默认不动，岩护盾平局前进1为例外；不移动不触雷 |
| BR-12 | 普通前进/爆炸回退仅检查落脚，不检查途中；自雷也能触发。空间换位明确不触发目标雷；免疫或焚毁按角色规则处理，均不因保留原位重复检查同一落脚 |
| BR-13 | 每次落脚只引爆1枚，优先非踏入方布置的雷；同阶其他雷保留 |
| BR-14 | 默认爆炸退10最低0；踏雷者对手为若娜瓦时退13。每次先按规则选定1雷，再判焚毁/免疫/普通爆炸及雷系弃牌，发生回退才检查新落脚形成连锁 |
| BR-15 | 普通到达/超过40立即停止后续回合并显示登顶结果、信标停40；若本轮有合法伊斯塔露回溯机会，结果仅候选，机会结束后才永久结算和记账；同轮同时登顶处理见3.11节 |
| BR-16 | 先完成当前出牌界面的合法即时技能，再按有效手牌确定本轮出牌者；纳贝里士0牌补到牌可出，若娜瓦消耗末牌后跳过。锁定末张扣至0仍须参与当前揭牌，不能误转单向出牌 |
| BR-17 | 先结算全部当前效果：判猜拳、败方补牌、移动、爆炸/弃牌及可用回溯，再确认登顶或双方耗尽比高，同阶平；不可在补牌或雷弃牌处理前提前以耗尽结束 |
| BR-18 | 实际出牌在确认时从可用手牌扣除一次，但直到统一亮牌才进入公开历史；已锁定待揭示牌必须参与本轮，不能因可用牌数先变为0提前触发耗尽终局；准备销毁牌与出牌历史严格分离 |
| BR-19 | 非法或失败操作不部分扣资源；重复确认不重复扣牌、扣雷、计战绩或解锁 |
| BR-20 | 私有信息默认不直接由UI/日志展示，允许推算；双方准备锁定后首次全面公开牌库分项和手牌总数。布耶尔可按技能查看范围内双方雷位；阿斯莫代的移雷窗口仅显示己方布雷坐标，不显示或允许移动敌雷；授权结果仅施法者可见，AI无额外内存权限 |
| BR-21 | 首次打开显示登录/注册模态框，登录后才进首页；本地主账号P1、Guest_P2不建档；账号切换/退出仅允许首页 |
| BR-22 | 12名常规角色＋1初始锁定融合角色，完整名单与技能见CH-01～CH-13；黄金莱茵多特击败纳贝里士永久解锁到主账号；设置/选角可测试解锁或重置锁定状态，不清空其他账号资料 |
| BR-23 | 房间仅2个活跃席位、无观战；房主P1、加入者P2；4～6位数字/字母码可复制或手输；双方就绪进入选角；闲置超过10分钟或房主退出解散，满员/已开局拒绝加入 |
| BR-24 | 联机初选单张15秒；选角、准备确认、技能选择确认及锁牌等当前等待步骤各45秒。超时随机选角/取牌、放弃未施放技能、代出合法可出花色中数量最多的牌；仅剩冰冻花色时按强制出牌规则，不因超时直接判负 |
| BR-25 | 不保存未完对局、不续连。本地/AI主动退出或重开二次确认后作废，不计战绩或解锁；刷新视为中断作废。联机关闭、刷新或退出判留存方胜并记战绩 |
| BR-26 | 自动BGM按场景及领先高度区间选择，1.5秒淡入淡出；爆炸降低阶数不回切低阶曲。手动选曲锁定当前曲，恢复自动或新局才解除 |
| BR-27 | UI采用白昼天空岛圣殿与笔直天梯，0～15山林石阶、16～30覆雪冰阶、31～40浮空玉阶及终点门；角色同阶左右分立，不改变业务阶数 |
| BR-28 | 角色特定规则覆盖冲突的基础规则；冰系魔神压制先于纳贝里士来源被动初始化及主动资格判断；融合黄金来源能力不受该压制 |
| BR-29 | 所有主动技能入口属于每回合“打出牌界面”；双方先完成出牌前主动技能选择/操作确认，再选择并锁定手牌；伊斯塔露仅在同界面的本轮结算展示区操作；普通准备与首页不提供施法入口 |
| BR-30 | 主动次数按每局独立计数；激活前条件不满足/非法目标/资源不足不部分生效。条件型技能激活即扣，未触发不返还；阿斯莫代首次显示己方布雷坐标时暂扣1次，成功移雷后保留扣次，明确取消移雷则返还；同一目标窗口内重选或改落点不重复扣次；回溯次数不被任何回溯返还 |

| BR-34 | 每轮先完成合法即时技能，再确定需出牌者；判猜拳后先处理失败补牌，再算移动/炸弹/弃牌，再给回溯机会，最后确认终局；主动补牌不能在已经确认结束的局外复活对局 |

### 3.4 v1.1资源守恒与技能例外

- 初选仍为双方各30张、公共库剩30张；每花色最初30不变。
- 任意稳定时点：公共库＋双方可用手牌＋已锁定待揭示牌＋有效公开出牌历史＋秘密销毁区＝90。秘密销毁区包括普通/技能换雷的消耗牌与雷炸随机弃牌；被回溯撤销的历史不再计入有效账本。
- 炼金转化只改变花色，不改变实体牌总数。因此游戏中不再要求每种花色恒为30，也不能用初始30直接反推当前敌手组成而忽略转化。
- 准备中令H为本人手牌、B为本人库存加场上雷、B0为初始雷数（默认3、巴尔泽布4），G为成功享受首次黄金折扣的次数（0或1），N为有效纳贝里士被动多获得的牌数，则H＋2B＝30＋2B0＋G＋N。该式只用于准备阶段，不延伸至有出牌、爆炸及其他技能的对局阶段。
- 无相关准备被动的默认角色仍有H＋2B＝36、手牌28～36偶数；巴尔泽布对应38且上限5。黄金首次1牌兑换、纳贝里士1雷3牌与融合效果会破坏统一的偶数手牌范围；不能给所有角色套用28～36或公共余量必为偶数。
- 公共库在准备后仍可因水系败方摸1、生命主动抽3而变化，应实时更新公开总数及花色分项；回溯则恢复本轮对应公共库。正常出牌、兑换消耗或随机弃牌不返库，合法回溯恢复不是另加洗牌/回收机制。
- 默认雷上限4、巴尔泽布5；若娜瓦技能不突破上限；空间移雷保留原所有者；焚毁、爆炸销毁后从原所有者总量中扣除；回溯应恢复原归属和数量。
- 普通牌库不足2、生命被动兑换不足3均整体拒绝且不扣雷。生命免费抽3在不足3时不消费次数、不部分抽取；水系已激活后牌库为0则不能凭空生成牌，其效果和次数处理见3.12节。

右上角“旋曜玉帛”风格播放器与设置需提供：播放/暂停、上一首/下一首、单曲循环/自动随场景切歌切换、BGM音量0～100%、BGM静音、SFX音量0～100%、SFX静音、镜头自动跟随开关。

浏览器首次拦截自动播放时，播放器显示实际未播放/受限状态；用户首次点击任意页面按钮（如登录、开始）时立即唤醒AudioContext恢复允许的播放。用户明确暂停或静音时，不因普通按钮点击违背其设置。音效至少覆盖点击、选牌、抛硬币、兑换、布雷/调整、锁定、亮牌、攀爬、爆炸、技能释放/压制/回溯和胜负；敌方私有操作的音效不得直接泄露花色或坐标。

### 3.9 边界解释与版本衔接

以下是为了使已裁决要求形成可操作验收而采用的最小衔接解释，属于本次修订的可审阅内容，不声称用户另行指定了这些细节，也不重开Q-01～Q-12：

1. **联机准备超时**：45秒针对一次“完成本人准备并确认”的步骤。期间兑换、移动、撤回不另起倒计时；超时保留已经合法完成的操作，直接锁定本人准备，不额外随机兑换、布雷或撤雷。与“操作次数不限”相容：无次数额度，但有联机时间限制。
2. **自动出牌并列**：先限定合法可出花色，再从数量同为最多的并列项选择任一；仅剩冻牌时遵守强制出牌例外。不额外要求并列项概率分布。自动与人工确认竞争时只能成功一次。
3. **房间空闲与对局边界**：10分钟空闲从最后一次有效房间活动起算，开始选角即视为对局已开始；尚未启动选角的单人等待房间解散不生成虚构胜负。已开始的联机对局因房主退出解散时，先确认留存者胜利再离开房间。若选角未完成即发生有效对局退出，历史中未选择的角色记为“未选择”，阶数为当时实际值，不虚构角色或解锁。
4. **关闭端存储边界**：要求留存端立即完成本账号胜利记录；不要求在已经关闭的端强行执行败绩写入，也不增加重连、跨账号写入或服务端数据恢复。
5. **性能测量**：100ms针对操作后可见反馈，不是完整攀爬动画或1.5秒音轨过渡时长。未来验收记录实际硬件、浏览器版本、资源缓存与网络条件，不将未定义的硬件环境虚构成已验证事实。

### 3.11 回合技能时序、结算与回溯

本节描述玩家可观察的业务顺序，不是程序状态机或实现设计。时间技能在结算展示时使用，是“所有主动在打出牌界面”的专门子区域，不应被改为提前施放。

#### 3.11.1 同一出牌界面的业务子步骤

1. 进入本轮打出牌界面，记录回溯所指的业务起点：本轮任何主动操作之前。先呈现冰系压制、持续护盾及可用技能次数。
2. 普通主动在技能操作区释放，合法即时效果当场生效；水系激活记为本轮条件效果。双方先各自完成技能选择/操作确认，再进入同界面的手牌选择与锁定；本地双人依先手、后手经交接遮罩完成技能操作，再进入选牌锁牌。该顺序避免对已经锁定的牌追加冻结并迫使改牌。
3. 在即时技能全部完成后确定本轮需出牌者：生命补牌可使0牌恢复出牌，死亡消耗最后1牌可使本人无牌跳过；已确定有牌者确认锁牌后即使扣至0，仍参与本轮揭示。不能在已有确认终局之后重新开放技能复活。
4. 仍有牌者在合法牌型中暗选，确认前可改、后不可改。冻结排除相应牌型；如果仅剩被冻结花色，允许强制出牌并挂载半基础步数效果。各方齐锁后同时揭示。
5. 双方都出牌时判定真实猜拳胜/负/平；先执行水系已激活的败方摸牌，再计算胜利加步、冰冻基础减半、火连胜或岩护盾平局移动。单向出牌不属于真实猜拳获胜，不触发风/岩/水获胜额外步或火连胜。
6. 执行本轮应有移动、落脚选雷、免疫/焚毁/爆炸及雷弃牌，按新落脚继续实际回退连锁。双方护盾平局均移动时作为同一轮同时发生的结果处理，不依程序先处理P1来决定胜者。
7. 展示当轮结果及仍可使用的时间回溯入口。可用回溯者选择施放或放弃；联机该决定45秒，超时视为放弃。回溯成功则回到本轮技能操作前重新进行，不能接着用被撤销的出牌自动结算。
8. 回溯机会结束后确认本轮结果：有一方登顶则胜；双方同一轮同时登顶则平局；否则双方手牌都耗尽比较最终阶数，同阶平。未结束时进入下一轮并推进持续状态的回合数；结果只在不可再回溯时写入战绩/解锁。

本地私有技能操作及暗选均通过交接遮罩；侦测结果在交接前隐藏。AI/联机同样不得在另一方技能操作未完成前提前锁牌。相互竞争同一雷、最后公共牌或改变对方位置的即时技能，按当前已生效状态检查后续操作合法性；需要同轮冲突定序时，本版采用硬币先后手顺序，不以网络到达快慢决定规则。激活前失败目标操作不消耗次数或资源；阿斯莫代仅能看到己方雷坐标，首次显示暂扣一次，同窗口重选不二扣，明确取消移雷返还该次，确认成功移动后保留扣次。

### 3.13 AI、测试开关与重新开始

AI保持“简单”“困难”两档；玩家可在AI对战选角环节手动指定AI参赛角色，并查看其完整信标/技能。没有用户手动指定时允许正常AI选角；已手动指定且合法时不能暗中改成另一个角色。可选集合与本客户端角色解锁/测试状态一致；本地Guest_P2不独立存档，使用本次选角展示的可选角色范围。

两档AI都可进行合法技能操作，但决策输入不得直接包含玩家完整手牌、库存雷或未授权暗雷坐标。布耶尔合法侦测结果可以被使用；阿斯莫代仅在合法移雷窗口查看并移动AI自身布置的雷，不得查看玩家雷坐标。不能为了困难难度预读后再伪装成猜测。AI遵守每局次数、魔神压制、冻结合法牌型、技能时点与回溯窗口。未给出胜率差、搜索深度或具体算法要求，不在需求阶段虚构这些数值。

设置页与选角页均提供明确标识“测试用途”的一键解锁/重置融合角色开关，只作用于当前客户端登录主账号的融合解锁状态。解锁不增加场次/胜场，不伪造“黄金战胜纳贝里士”的历史；重置只重新锁定该角色，不删除账号、文件、战绩、设置或其他角色进度。不能在正在进行的对局中通过设置重置改变已确认角色；选角中重置使尚未确认的融合选择失效，需重新选角。正常达成条件的解锁永久保留，除非用户显式执行测试重置。

“重新开始”作为独立可见功能：本地/AI对局中点击后要求二次确认，取消继续，确认使旧未完局作废并回到该模式选角；新局重新抛币和选牌，重置牌库、位置、炸弹、主动次数、首次被动、连胜、护盾/冰冻、回溯记录与音乐区间。保留既有账号资料、正常/测试解锁状态、设置；保留AI难度与手动角色作为可编辑默认选择，不自动跳过选角。已正常确认完成的上一局不能用“重新开始”擦除战绩。

联机重开不得单方面清空对方对局。进行中选择重开按退出当前房间处理，使留存方依既定规则获胜；随后重新建房/加入并双方就绪开始新局，不直接复用旧局资源。未增加未经双方同意的房内直接重置功能。
