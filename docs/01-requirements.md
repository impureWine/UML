## 1. 项目目标与范围

### 1.1 目标

提供PC桌面浏览器中的《40阶登山博弈游戏》。玩家先选角、抛硬币并交替选取猜拳牌，再在开局唯一准备阶段兑换手牌与炸弹、秘密布雷，随后通过同时亮牌的猜拳对战登山。支持本地双人、AI、房间码邀请联机三种模式。

界面采用《原神》白昼天空岛圣殿与笔直向上的立体天梯风格，以程序化立体角色、阶数高亮、镜头跟随、背景音乐及音效呈现游戏过程。该视觉裁决取代初稿的“盘山阶梯”要求。

前端LocalStorage在同一浏览器同源站点范围内保存多个本地账号，各账号分别保留战绩、角色解锁进度和设置。无需外部数据库；不提供云账号、跨设备恢复、未完对局保存或断线续局。

### 1.2 阶段与交付约束

本阶段只修订需求分析说明书和PlantUML用例图，不创建程序源代码、不安装依赖、不提前实现功能，不生成类设计、接口设计或开发任务。LocalStorage、Web Audio API和允许的通信方式是用户已指定的需求约束；本版只记载约束，不开展系统设计。

流程保持为：需求分析 → 系统分析 → 系统设计 → 开发任务拆分 → AI生成程序 → 人工运行测试 → 反馈修改 → 最终验收。每阶段完成后由用户确认；进入程序开发还必须等待用户明确说“开始编程”。删除任何文件必须先征得用户允许。

### 1.3 v1.0与v1.1的边界

v1.0包含账号、三个对战模式、开局选角与隐藏角色解锁框架、基础卡牌和炸弹规则、角色与规则图鉴、地图、播放器、设置、计时、异常退出及结果持久化。

v1.1将补充13名角色的完整名单、外观、专属主动与被动技能及数值，以及特定角色触发《Termination of Desires》《Rage Beneath the Mountains》的条件。v1.0不虚构这些内容，也不把该已安排的补充当作尚未裁决的Q项。后续技能若改变手牌、炸弹或移动规则，应在v1.1明确覆盖范围，并重新核对本版资源不变量及验收样例。

聊天、公屏、公开匹配、观战、排行榜、付费、云同步均不在本版范围。六首指定音乐在v1.0均须内置可播放，两首特殊角色曲目的自动触发条件留给v1.1。

### 1.4 编号与状态约定

FR为功能需求，BR为业务规则，UC为用例，AC为未来人工验收标准，NFR为非功能需求。Q-01～Q-12保留为**已裁决、已闭合的决定记录**，不再作为待确认清单。

本版保留原FR-01～FR-46、UC-01～UC-24、AC-01～AC-47编号并更新内容，新增编号顺延。AC定义的是验收口径，文档检查不代表软件功能、音画或性能已通过验收。第3.9节列出把最终裁决衔接成完整流程所采用的边界解释，避免将其误称为用户另行指定的细节。

## 2. 系统参与者分析

### 2.1 外部参与者

| 编号 | 参与者 | 目标与职责 | 边界 |
| --- | --- | --- | --- |
| ACT-01 | 未登录使用者 | 在登录/注册模态框中注册或登录 | 首次打开为未登录状态，不能免登录进入首页；不是Guest_P2 |
| ACT-02 | 本地账号使用者 | 查看首页、战绩及解锁进度，管理设置和音乐，开始对战、创建或加入房间 | 当前客户端只有一个登录主账号；账号切换/退出仅允许在首页操作 |
| ACT-03 | 对局玩家（P1/P2） | 选角、就绪、选牌、准备、出牌、查看本人信息及公开结果 | 是业务席位角色；本地和联机有两位人类，AI模式仅人类是外部参与者 |
| ACT-04 | 本地临时访客Guest_P2 | 在主账号发起的本地对局中操作P2 | ACT-03的特化；无需第二账号，不独立保存战绩、成就或设置，不具有ACT-02的账号管理权限 |

同一人可在首页扮演ACT-02，在对局扮演ACT-03。房主、受邀者、先手和后手是场景身份，不是额外账号类型。

### 2.2 席位与账号归属

| 模式 | P1 | P2 | 本客户端保存对象 |
| --- | --- | --- | --- |
| 本地双人 | 当前登录主账号 | Guest_P2 | 仅主账号，按P1视角记录 |
| AI对战 | 当前登录主账号 | 系统AI | 仅主账号；AI不独立建档 |
| 联机对战 | 创建房间的房主 | 输入房间码加入者 | 各客户端只保存自己当前主账号；加入者按P2视角记录，不替对手账号写入 |

本地不允许同一主账号同时占P1/P2并计算两份战绩。联机房主固定P1不代表必定先选牌；选牌先手由公平硬币决定。

### 2.3 相关方及系统边界

教师和验收人员是项目评审相关方，不因此增加后台管理功能。AI、LocalStorage、地图、计时器、播放器、合成器均属于系统内部能力或运行环境，不作为外部参与者。用例图不虚构外部数据库、云账号或音乐服务。

联机允许采用同机多窗口/跨标签页的BroadcastChannel加LocalStorage事件同步，或轻量级局域网消息同步；具体方案在系统设计阶段选择。本版不承诺公网异地联机，也不将同源本地存储描述为跨设备共享账号。

## 3. 业务规则与验收解释

### 3.1 术语

| 术语 | 定义 |
| --- | --- |
| 公共牌库 | 初始石头、剪刀、布各30张，共90张；初选及库存雷换牌从中取牌 |
| 可用手牌 | 本人尚可选取进行兑换或出牌的牌；确认出牌后扣除，揭示前不公开其花色 |
| 秘密销毁区 | 存放准备时“2牌换1雷”交出的牌；不回库，具体花色不向对手展示 |
| 公开出牌历史 | 在应出牌者均锁定、统一揭示后，记录双方实际打出的牌；包括败方、平局和单向出牌，不回库 |
| 库存炸弹 | 本人未布置的炸弹；只有该类炸弹可用于“1雷换2牌” |
| 场上炸弹 | 放在1～39阶、具有所有者且尚未引爆的炸弹 |
| 一次落脚 | 前进结束或一次爆炸回退结束后到达某阶；不包含途中经过、原地停留和视觉站位偏移 |
| 房间准备就绪 | 联机双方进入房间后各点击就绪，二者完成后启动选角；不同于选牌后的唯一准备阶段 |
| 唯一准备阶段 | 双方各取满30张牌后、第1回合之前的一次性兑换、布雷及锁定阶段 |
| 领先高度 | 双方当前所在阶数的最大值；自动BGM另记本局已达到的最高音乐区间以避免爆炸降级回切 |
| 当前客户端主账号 | 本客户端已登录且从选角至对局结束期间被锁定的账号；联机加入者可以位于P2 |

### 3.2 业务流程

登录/注册 → 首页选择模式 → 确定席位（联机先入房并双方就绪）→ 选择角色 → 初始化资源并抛硬币 → 一人一张交替初选至双方各30张 → 唯一准备阶段 → 双方锁定后统一公开规定信息 → 连续暗选出牌、亮牌、移动及连锁结算 → 登顶或耗尽判胜 → 保存主账号结果 → 返回首页。

本地准备采用硬币确定的先手先操作、锁定、交接遮罩、后手操作并锁定；AI及联机双方独立准备。图中的include/extend只表示必需子目标或条件行为，不用于表达上述先后顺序。

### 3.3 基础规则

| 编号 | 规则 |
| --- | --- |
| BR-01 | 每局公共牌库90张，三花色各30；双方起点0阶，各有3枚库存雷；独立新局不保留上局资源 |
| BR-02 | 公平硬币正反各1/2；正面P1先选，反面P2先选；之后一人一张交替，直至各30张 |
| BR-03 | 初选结束双方共取60张、公共库剩30张；先手只影响选牌及本地准备顺序，不赋予回合出牌或胜负优先权 |
| BR-04 | 准备只出现一次；首回合开始后不能再兑换、布雷、移动或撤回雷 |
| BR-05 | 每人库存雷＋本人场上未爆雷最多4枚；布置、撤回、移动不改变本人总雷数、不释放上限额度 |
| BR-06 | 未锁定准备时，用实际持有的2张指定牌换1库存雷；可同花色两张，所交牌进入秘密销毁区，不回公共库 |
| BR-07 | 只有库存雷可换牌：消耗1枚，从剩余实体牌中等概率不放回抽2张；库不足2张则整笔拒绝，不扣雷 |
| BR-08 | 准备在资源约束内不限制兑换次数；联机仍受准备确认倒计时约束；结束后手牌按实际数量保留，不重置成30 |
| BR-09 | 雷只可布于1～39阶，可同阶多枚；本人准备锁定前可移动或撤回本人本次准备放置的雷，锁定后不可撤销确认、不可调整 |
| BR-10 | 双方有牌时各暗选1张，确认前可改选、确认后不可改；应出牌者全部锁定后同时亮牌；石头胜剪刀、剪刀胜布、布胜石头 |
| BR-11 | 胜者按获胜牌前进：剪刀2、布3、石头5；平局双方及败方不动，停留不触雷 |
| BR-12 | 只在实际移动后的落脚点检查雷，不检查途中台阶；不分敌我，本人雷也能引爆 |
| BR-13 | 每次落脚只引爆1枚，优先非踏入方布置的雷；同阶其他雷保留 |
| BR-14 | 每枚雷引爆后销毁并回退10阶，最低0；检查新落脚，仍有雷则继续连锁，直至无雷 |
| BR-15 | 达到或超过40立即获胜，模型停40阶终点大门区域的山顶王座；不显示越界阶数或等待下一轮 |
| BR-16 | 本轮需要出牌的玩家按本轮选牌开始前是否有牌确定；无牌者跳过，有牌方单向出牌时按2/3/5步推进并结算踩雷。已经锁定最后一张、扣牌后变为0的玩家仍参与当前回合，不因此改为跳过或使对手单向推进 |
| BR-17 | 双方耗尽时先完成当轮移动和全部连爆，再比较最终阶数；高者胜、同阶平。已登顶胜利优先 |
| BR-18 | 实际出牌在确认时从可用手牌扣除一次，但直到统一亮牌才进入公开历史；已锁定待揭示牌必须参与本轮，不能因可用牌数先变为0提前触发耗尽终局；准备销毁牌与出牌历史严格分离 |
| BR-19 | 非法或失败操作不部分扣资源；重复确认不重复扣牌、扣雷、计战绩或解锁 |
| BR-20 | 保密指常规UI与日志不直接展示敌方私有信息，允许玩家依公开规则及数值推算；公共花色与双方手牌总数的首次全面公开仅在双方准备锁定后 |
| BR-21 | 首次打开显示登录/注册模态框，登录后才进首页；本地主账号P1、Guest_P2不建档；账号切换/退出仅允许首页 |
| BR-22 | 12名常规角色＋1名初始锁定融合角色“莱茵多特/纳贝里士”；主账号使用“黄金”莱茵多特击败“纳贝里士”时解锁融合角色 |
| BR-23 | 房间仅2个活跃席位、无观战；房主P1、加入者P2；4～6位数字/字母码可复制或手输；双方就绪进入选角；闲置超过10分钟或房主退出解散，满员/已开局拒绝加入 |
| BR-24 | 联机选择/确认步骤45秒，交替初选每次15秒；超时自动代操作，不按超时判负：随机选角、按剩余实体牌随机取牌、出当前数量最多的手牌 |
| BR-25 | 不保存未完对局、不续连。本地/AI主动退出或重开二次确认后作废，不计战绩或解锁；刷新视为中断作废。联机关闭、刷新或退出判留存方胜并记战绩 |
| BR-26 | 自动BGM按场景及领先高度区间选择，1.5秒淡入淡出；爆炸降低阶数不回切低阶曲。手动选曲锁定当前曲，恢复自动或新局才解除 |

### 3.4 资源守恒与可达边界

- 初选完成：P1手牌30＋P2手牌30＋公共库30＝90。
- 准备阶段：公共库＋双方手牌＋秘密销毁牌＝90。
- 对本人准备阶段，令H为手牌数，B为库存加场上本人雷，则H＋2B＝36。布雷、移动与撤回均不改变此式；0≤B≤4，因此H只可能为28、30、32、34、36。
- 准备期间不存在正常可达的“手牌为0”情形；也不额外设置30张手牌上限。
- 初选后公共库从30张开始只按2张减少，正常准备余量为偶数；“余1张拒绝换牌”只能作为人为边界检查，正常不足2是0张。
- 对局中，公共库＋双方可用手牌＋已锁定待揭示牌＋公开出牌历史＋秘密销毁牌＝90。待揭示牌统一亮出后转入公开历史，不能重复计数。
- 双方准备锁定后公共库及各花色余量不再变化；已出牌和秘密销毁牌都不回库。出牌、引爆发生后，准备阶段H＋2B＝36不再适用。
- 数量不得为负；不自行洗牌、补库或回收销毁牌。v1.1技能补充前，以上均按无技能影响的基础规则核对。

### 3.5 公开与保密时点

| 信息 | 选牌及准备进行中 | 双方准备锁定后至对局结束 |
| --- | --- | --- |
| 公共牌库剩余总数 | 对双方显示，可随实际取牌更新 | 对双方显示 |
| 公共石头/剪刀/布分项余量 | 不公开显示；不能在对手界面或日志实时刷新分项计数 | 进入第1回合前一次性公开，此后保持与真实余量一致 |
| 本人手牌组成与数量 | 本人可见 | 本人可见 |
| 对手手牌总数 | 不提前提供完整公开牌数栏；交替顺序或本人操作自然可推算的信息无需消除 | 首回合前与其他规定信息一并公开，之后随实际出牌更新 |
| 对手手牌组成 | UI/日志不直接展示 | UI/日志不直接展示；允许数学推算 |
| 本轮暗选或待揭示牌 | 不适用出牌回合 | 本人可见；所有需出牌者锁定前对手不可见，不能提前写入公开历史 |
| 本人库存雷 | 本人可见 | 本人可见 |
| 对手库存雷 | UI/日志不直接展示 | UI/日志不直接展示；推算出数量也不属于违规 |
| 本人未爆雷位置 | 按住查看时显示，松开/失焦/交接即隐藏 | 同左；锁定后不允许再调整 |
| 对手未爆雷位置、同阶雷数量 | 不直接展示 | 不直接展示；不通过提示、动画、声音或日志提前揭露 |
| 兑换销毁牌花色 | 仅本人私有记录可见 | 仍属秘密销毁区，不混入公开历史 |
| 已引爆雷的归属与位置 | 准备期间不触发 | 每次实际引爆时由战斗日志公开 |
| 实际打出的牌 | 不适用 | 所需玩家锁定后统一揭示并记录，包括败方、平局及单向出牌 |

Q-01已选择选项A：算牌是游戏的一部分。例如不存在秘密销毁影响时，可由初始每花色30张减公共余量、本人持牌及公开已出牌推算对方数量；准备有秘密销毁时不能无条件套用旧的初选公式。准备阶段H＋2B也可能带来雷量推断，均不需要屏蔽。系统不能为了“防推算”隐藏已要求公开的数据，也不能以“可推算”为由直接显示敌方秘密。

同机防窥依靠交接确认遮罩与玩家自觉避让；遮罩覆盖上一操作者的手牌、库存、雷位及暗选内容。验收不要求抵抗F12、内存调试、设备所有者修改或恶意旁观。AI可使用自己的合法资源以及公开信息，但没有读取敌方隐藏资源的特权。

| 最近对局历史 | 模式、从主账号席位视角判断的胜/负/平、双方所选角色、双方最终停留阶数、结束时间戳；按结束时间查看最近记录，不虚构用户未给出的条数上限 |
| 本地/AI作废局 | 不增加总场次及胜负平，不写入已完成历史，不触发解锁 |
| 联机留存方获胜 | 在留存客户端按其主账号席位保存胜利；不依赖已关闭或刷新的另一客户端重新上线，也不声称能跨客户端替其持久化败绩 |
| 个性化设置 | 第3.8节的音乐、音效及镜头设置按主账号保存；Guest_P2与AI不独立保存 |

主账号在联机中可能是P2，战绩与解锁必须按该席位判断；不能写成“所有模式只给P1记账”。角色已解锁后再次满足条件不会重复添加。角色未选定就中断时，不虚构双方角色，也不触发缺少角色条件的解锁。

### 3.8 音频、控制项与场景映射

六首指定曲目与全部交互音效均通过Web Audio API内置多轨乐谱合成器实时生成，正常发声不依赖外部音频文件。不能用曲名标签、统一提示音或一段无关旋律冒充六首曲目的旋律。另提供“挂载本地MP3文件”可选入口，加载失败静默回退内置合成器，不弹出阻塞错误。

| 曲目 | 自动播放场景/区间 |
| --- | --- |
| Twilight Serenity（宁静的黄昏） | 首页、图鉴、选角、终局结算 |
| Bustling Afternoon in Mondstadt（蒙德城繁忙的午后） | 选牌、唯一准备阶段；登山最高区间仍为0～15阶 |
| Moonlike Smile（皎洁的笑颜） | 登山领先高度达到16～30阶，且本局未达到更高音乐区间 |
| Rex Incognito（尘世闲游） | 登山领先高度达到31～39阶；到达40即进入终局场景 |
| Termination of Desires（斩雾破竹） | v1.0已内置、可手动选择播放；特定角色在场优先切换条件由v1.1补充 |
| Rage Beneath the Mountains（山峦的震怒） | v1.0已内置、可手动选择播放；特定角色在场优先切换条件由v1.1补充 |

自动音乐以领先者所达区间推进：本局已达到31～39阶区间后，即使爆炸退回低阶，也不自动降回低阶曲目；已达到16～30时同理。首页、图鉴、选角、终局仍按场景映射，不被高阶音乐记录阻止。新局重置区间进度。自动曲目切换使用1.5秒平滑淡入淡出。

右上角“旋曜玉帛”风格播放器与设置需提供：播放/暂停、上一首/下一首、单曲循环/自动随场景切歌切换、BGM音量0～100%、BGM静音、SFX音量0～100%、SFX静音、镜头自动跟随开关。

手动切歌后进入“手动锁定当前曲目”，不被场景变化覆盖，直至用户恢复“自动随阶段切歌”或开启新局。恢复自动应回到当前场景与本局已达到的音乐区间；开启新局解除手动锁定并重置区间，但不能擅自取消用户静音或重设音量。暂停、静音属于播放控制，不因为自动选曲而失效。

浏览器首次拦截自动播放时，播放器显示实际未播放/受限状态；用户首次点击任意页面按钮（如登录、开始）时立即唤醒AudioContext恢复允许的播放。用户明确暂停或静音时，不因普通按钮点击违背其设置。音效至少覆盖点击、选牌、抛硬币、兑换、布雷/调整、锁定、亮牌、攀爬、爆炸和胜负；敌方私有操作的音效不得直接泄露花色或坐标。

### 3.9 边界解释与版本衔接

以下是为了使已裁决要求形成可操作验收而采用的最小衔接解释，属于本次修订的可审阅内容，不声称用户另行指定了这些细节，也不重开Q-01～Q-12：

1. **联机准备超时**：45秒针对一次“完成本人准备并确认”的步骤。期间兑换、移动、撤回不另起倒计时；超时保留已经合法完成的操作，直接锁定本人准备，不额外随机兑换、布雷或撤雷。与“操作次数不限”相容：无次数额度，但有联机时间限制。
2. **自动出牌并列**：存在多个数量同为最多的花色时，从并列项选择任一花色；不额外要求并列项的概率分布。自动操作和人工确认竞争时只能成功一次。
3. **房间空闲与对局边界**：10分钟空闲从最后一次有效房间活动起算，开始选角即视为对局已开始；尚未启动选角的单人等待房间解散不生成虚构胜负。已开始的联机对局因房主退出解散时，先确认留存者胜利再离开房间。若选角未完成即发生有效对局退出，历史中未选择的角色记为“未选择”，阶数为当时实际值，不虚构角色或解锁。
4. **关闭端存储边界**：要求留存端立即完成本账号胜利记录；不要求在已经关闭的端强行执行败绩写入，也不增加重连、跨账号写入或服务端数据恢复。
5. **性能测量**：100ms针对操作后可见反馈，不是完整攀爬动画或1.5秒音轨过渡时长。未来验收记录实际硬件、浏览器版本、资源缓存与网络条件，不将未定义的硬件环境虚构成已验证事实。
